# 粘贴图片与富文本

## 使用方式

在源码或分栏模式的源码编辑区使用 `Ctrl+V`。截图、复制图片、资源管理器复制的图片文件，以及网页、Word、Electron 应用提供的标准 Windows HTML 剪贴板内容，都走同一导入流程。`Ctrl+Shift+V` 只插入纯文本。阅读区不接受编辑粘贴。

标题、粗体、斜体、删除线、链接、列表、引用、代码和普通表格转为 Markdown；不复刻字体、颜色、分页与页面布局。表格以首行为表头，合并单元格不承诺还原原布局。支持常见 span 内联样式表达的粗体、斜体和删除线。应用私有剪贴板格式没有通用解析器；只有纯文本时按纯文本粘贴。

内联 SVG 可作为本地图片导入；声明 `aria-hidden="true"` 的装饰 SVG 忽略。剪贴板本身没有提供的 CSS 背景图、图标或空菜单文字无法恢复；不生成空链接、空列表项或空标题。带链接的图片保留其页面链接，下载失败时把图片来源提示与页面链接分开，避免生成 Markdown 不支持的嵌套链接。

状态栏显示准备或导入提示，不改变工具栏、编辑区的布局。后台转换与图片处理完成后，在原光标或选区位置一次插入，整段内容可一次撤销和重做。等待期间可以编辑其他位置；插入位置会跟随前面的编辑。如果原选区被修改，则取消本次粘贴，避免覆盖新内容。用户已经移开的选区尽量保持原位置。

`Esc` 或源码区的撤销操作会取消等待中的粘贴；再次粘贴富文本会替换前一次待处理任务。切换文档、关闭窗口或手动另存为也会取消待处理任务。迟到结果不再修改正文。已发出的网络请求可能继续至其超时，但不会再插入结果；已成功写入的图片保留。

含图片的新文档先要求保存 Markdown，以确定图片目录；取消保存则取消这次粘贴。无图片的富文本无需先保存。

## 图片与网络

图片保存在 Markdown 同级的 `文档名.assets/nm-<内容摘要>.<格式>`，正文使用编码后的相对路径。支持 PNG、JPEG、GIF、WebP、BMP、SVG；重复内容复用附件文件。Word HTML 中的临时图片路径会尝试匹配同次剪贴板中的 PNG/JPEG RTF 图片；单图也可使用剪贴板自带的位图。无法取得图片时不会编造本地引用。

HTTP/HTTPS 图片只在用户粘贴时下载，不携带浏览器 Cookie 或登录凭据，不自动重试；默认连接超时 **5 秒**、单张请求（包含响应体）总超时 **10 秒**、整批下载期限 **20 秒**，最多并发 **4** 个请求。整批期限不包括用户选择保存位置、HTML 转换和本地文件写入。队列中超出期限的图片也记录失败。

在设置的 **粘贴与下载** 分类中可分别选择连接（3/5/10/15/30 秒）、单张（5/10/20/30/60 秒）和整次粘贴（10/20/30/60/120 秒）超时，并可恢复默认。各级期限同时生效，实际等待取较短者；例如连接选 15 秒而单张选 10 秒时，仍受单张 10 秒限制。配置复用 `%APPDATA%/NativeMarkdown/layout.conf` 保存，重启后保留；仅用户修改值时更新，重复选择、切换分类、粘贴和退出不额外保存。配置写入失败时保留当前内存选择并在状态栏显示错误；每次开始图片导入时取一份快照，调整不影响已经开始的任务。

设置按 **外观与阅读 / Markdown 与预览 / 粘贴与下载** 分类。标题、分类栏和完成按钮保持固定，仅当前分类内容滚动。

图片上限为单张 **20 MiB**、每次粘贴 **50 张**、成功导入的不同图片合计 **100 MiB**。原始 HTML/RTF 剪贴板格式各最多读取 **16 MiB**；过大的格式会忽略，使用其他可用格式或保留图片失败位置。下载结果按图片内容特征识别格式，不把登录页面等 HTML 当图片保存。此检查不等于完整解码验证，损坏图片仍可能无法显示。

失败处保留原位置、说明及可用的 HTTP/HTTPS 来源链接，例如：

```markdown
[图片下载失败：示意图（下载超时）](<https://example.com/image.png>)
```

没有可用来源链接的截图、内嵌图片或应用私有地址，只保留文字失败提示。超限、服务器拒绝、认证图片、无效格式、缺失本地文件和附件写入失败也采用相同处理。不会为失败地址定时重试或建立下载缓存。

## 文件写入与另存为

仅在用户粘贴含图片的内容时创建附件目录、写入成功取得的图片。每个不同图片最多写入一次，不增加附件缓存、后台扫描或日志。附件采用临时文件完成后提交，未完成的临时文件自动清理；不覆盖已有的不同内容，路径不能越出文档目录。撤销正文、取消粘贴或放弃文档修改不会自动删除已成功写入的图片。

跨目录另存为时，仅复制正文仍引用的本应用附件，不扫描附件目录。保留附件原相对目录名，例如 `a.assets/`；即使 Markdown 改名为 `b.md`，引用仍然有效，也无需重写正文或清空编辑历史。原目录保留。目标已有不同内容、附件缺失或复制失败时中止另存为；本次新复制的文件回滚，原文档路径与保存基线不变。普通用户图片、网上链接及未引用附件不由此流程迁移。

## 验证边界

自动回归覆盖富文本结构、UTF-8 剪贴板片段偏移、内嵌图片、Word RTF 图片、重复文件复用、HTTP 下载及慢响应超时、失败链接、数量/大小限制、取消、另存为冲突和回滚。GPUI 回归覆盖剪贴板位图、纯文本快捷键、单次撤销重做、异步插入位置及文档切换隔离。

超时配置回归覆盖单张期限和整批期限分别截断慢响应，以及失败提示、来源链接和不写入失败附件。设置交互回归覆盖三个分类、三项超时、恢复默认及标题按钮和分类按钮坐标稳定；实际 Windows Debug 窗口核对过分类切换、修改连接超时、跨分类保留选择、恢复默认和外观页滚动时顶部导航固定。

持久化回归覆盖旧配置默认值、非法参数回退、文件保存与重读、默认值覆盖保存及写入失败。实际隔离 Debug 窗口中将连接超时改为 15 秒、方言改为 CommonMark、预览延迟改为 3 秒，退出重启后均恢复；启动正文也按 CommonMark 展示。重复选择同一超时，以及退出、重启和切换分类后，配置内容与文件修改时间保持不变。该检查针对配置文件，不代表进程或系统总体磁盘 I/O 测量。

实际 Windows Debug 窗口验证过合成 CF_HTML 内容的粘贴、图片显示、失败链接、撤销重做、保存并重开；也通过隔离 Chrome 打开本地网页，实际全选复制后粘贴，核对文字、表格、内嵌图片和失败链接。新文档的“含图粘贴 → 首次保存 → 继续导入”和“取消保存 → 取消粘贴”均已操作验证。测试使用工程 `tmp/` 下的隔离配置与文档，结束后恢复原剪贴板格式。

未完成桌面 Word、Edge 和公司内部 IM 的实际复制验收。Word 图片的证据来自合成 HTML/RTF 回归；内部 IM 的私有协议、登录图片及剪贴板内容仍需使用真实环境验证。不将测试和构建结果作为 CPU、内存或磁盘 I/O 无回归的保证。

### Hugging Face 实际剪贴板回归

用户提供了从 Qwen 模型文件页复制的 CF_HTML。已确认原实现把图片失败提示嵌进外层链接，并把剪贴板中的空菜单链接、空图标容器输出成空 Markdown 链接。确定性回归覆盖这两类结构及内联 SVG。使用同一捕获内容重放实际下载，Logo 成功取得；随后捕获到 3 秒连接阶段超时；3/5 秒预算交替对照中，5 秒预算的三次请求均成功，其中一次完整请求耗时约 3.86 秒。连接超时由 3 秒调整至 5 秒，单张总超时 10 秒、整批 20 秒和不自动重试保持不变。网络仍可能波动，不承诺所有图片一定下载成功。

修复后的实际 Debug 窗口也直接粘贴了用户当前的同一份剪贴板内容：Logo 本地化并正确显示，空菜单链接移除，Qwen 标题保持单行 Markdown 标题。没有覆盖用户剪贴板，也没有关闭或替换用户运行中的已安装程序。

原始捕获与重放结果位于 `tmp/paste-diagnosis/`，被 Git 忽略，不会随提交转移。手工网络回归入口为设置 `NATIVE_MARKDOWN_PASTE_REPLAY` 指向授权捕获的 HTML 文件，然后执行 `cargo test --locked replay_captured_clipboard -- --ignored --nocapture`；输出保留在捕获目录下独立的 `replay-*` 子目录。
